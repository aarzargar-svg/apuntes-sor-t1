## ⌨️ Comandos y pasos importantes

**Comprobar dónde estoy y moverme**

- `pwd`: muestra en qué carpeta estoy. Lo uso antes de tocar nada para comprobar que estoy en `.../Boveda_SOR/01_Practicas`.
- `cd B0_Prerrequisitos` / `cd B1_Entorno` / `cd B2_Ubuntu_Local`: entra en la carpeta recién clonada.
- `cd ..`: sube una carpeta, para volver a `01_Practicas` antes del siguiente clone.
- `ls`: lista los ficheros de la carpeta, para ver que se ha bajado el material.

**Clonar los tres repositorios**

- `git clone git@github.com:TU-USUARIO/bloque-0-prerequisitos.git B0_Prerrequisitos`: baja mi copia de Prerrequisitos por **SSH** (con historial, usa mi clave SSH) y la guarda en la carpeta `B0_Prerrequisitos`.
- `git clone https://github.com/TU-USUARIO/bloque-1-entorno.git B1_Entorno`: baja mi copia del Bloque 1 por **HTTPS** (no pide identificación porque el repo es público) y la guarda en `B1_Entorno`.
- `git clone git@github.com:TU-USUARIO/bloque-2-ubuntu-local.git B2_Ubuntu_Local`: baja mi copia de Boochan por **SSH** y la guarda en `B2_Ubuntu_Local`.

**Comprobar y subir cambios**

- `git status`: muestra el estado del repositorio. En la carpeta del ZIP da `fatal: not a git repository` (no hay `.git`); en el clon da `working tree clean`; tras crear `MIS_DATOS.md` lo marca como _untracked_.
- `git add .`: prepara todos los cambios para el commit.
- `git commit -m "Anadir mis datos de alumno"`: guarda los cambios en el historial local con un mensaje.
- `git push`: sube los commits de mi ordenador a mi repositorio en GitHub.
- `git remote -v`: muestra las direcciones remotas del repo. Tienen que llevar **mi usuario**, no `sor-iesjj`.

## 🤔 Respuestas a las preguntas

1. ¿Qué hace Use this template ? Después de pulsarlo, ¿sobre qué repositorio trabajas, el mío o el tuyo?

Crea en mi cuenta de GitHub un repositorio nuevo e independiente, con el mismo contenido que la plantilla pero con historial propio. No es un enlace al del profesor. Después trabajo sobre **el mío**. No soy colaborador del repositorio del profesor, así que un push contra él me daría un error 403 y no puedo estropear su material.

2. Te has bajado el Bloque 1 por HTTPS y no te ha pedido contraseña. ¿Por qué? ¿Cuándo sí te la habría pedido?

Porque los repositorios son públicos y para **leer** (clonar) no hace falta identificarse, igual que se puede leer una web sin registrarse. Identificarse hace falta para **escribir**. Me la habría pedido:

- en un `git push`, aunque el repo sea mío, y
- al clonar por HTTPS si hubiera creado mi copia como _Private_.

La clave SSH y el token sirven para subir, no para bajar.

3. En el Explorador, la carpeta del ZIP y la carpeta clonada se ven idénticas. ¿Qué tiene una que no tiene la otra, y qué tres cosas dejas de poder hacer sin ella?

La clonada tiene la carpeta oculta **`.git`**, donde vive el historial. El ZIP solo trae los ficheros. Sin `.git` dejo de poder:

usar comandos de Git (`git status`, `git log`, `git restore`...),
recuperar lo que borre (lo borrado, borrado está), y
subir mi trabajo a GitHub.

4. Anotas una duda en un fichero de la práctica, en el ordenador del aula. ¿Qué tienes que hacer para encontrar el sábado en casa?

Escribirla en mi `MIS_NOTAS.md` (no encima del texto del profesor), que está en mi repositorio, y subirla desde el aula con `git status → git add . → git commit -m "..." → git push`. El sábado en casa hago `git pull` (o clono si no lo tengo) y la tengo. Si no la subo, se queda en el ordenador del aula.
